# Phase 7 adversarial review and neutral adjudication design

**Status:** Approved architecture with three design amendments, 3 October 2026; ready for user approval before implementation planning. Architectural design only; no Phase 7 production implementation or implementation plan is authorized by this document.
**Accepted input baseline:** Phase 6 commit e4dd4e09699f755dd0fe7b7bc3dd8be4e11f7ee1; Stage 1 and Gate 30 passed. This design does not change its evidence semantics.
**Governing sources:** [master design specification](../../specs/master-design-spec.md), especially invariants 1–15, sections 31–37 and the Phase 7 exit criteria; [Phase 6 downstream authority design](2026-10-01-phase-6-downstream-authority-consolidation-design.md); ADR-026–036; [Phase 6 final review](../../reviews/phase-6-final-review.md).

## 1. Executive summary

Phase 7 decides which **claim-specific novelty conclusions** the authoritative, bounded Phase 6 evidence permits. It uses controlled adversarial adjudication with separate input clarification and typed research escalation (the approved B+ architecture). A deterministic case builder binds one repository-validated Phase6AssessmentView and one sealed assessment context. Independent prosecutor and defender first passes produce structured proposals. Material disputes receive at most one rebuttal per side, and disputes with verdict-relevant possible resolutions receive role-blinded, order-counterbalanced neutral judging. A deterministic policy alone grants verdict permission. Its output is a repository-frozen adjudication that Phase 8 may render but cannot revise.

An external evidence gap can request another pass through the existing Phases 3–6 pipeline; an underspecified target requires input clarification or abstention. Any completed escalation that changes verdict-relevant evidence or research state creates a new sealed assessment context, **supersedes** the old Phase 7 attempt and starts fresh role passes, even when it finds no new source. Phase 7 neither searches directly nor creates verified evidence. The strong-positive verdict exists in the contract but cannot be emitted until later robustness and domain qualifications are genuinely available.

## 2. Context and Phase 6 handoff

The sole authoritative evidence input is Phase6AssessmentView returned by EvidenceGraphRepository.load_phase6_assessment(assessment_id, snapshot_id). The view retains full ClassifiedComparison chains, exact verifier-cited passages, source/version and chronology, authorized graph relations, semantic-only statuses, target/combination profiles, candidate outcomes, bounded coverage, lineage, multi-source context and patent screening. Constructing or deserializing the same Pydantic shape confers no authority. A semantic-only comparison can inform uncertainty but cannot be cited as an authorized graph relation.

CanonicalIdeaRepresentation, the reconciled MCUGraph or MCUVersion, Phase 2 SufficiencyAssessment, and Phase 3/4 plan, coverage, BranchState, StopAssessment and BudgetUsage are **non-evidence policy inputs**. Phase 7 obtains them through a validated assessment-lifecycle input manifest, not arbitrary caller arguments. The manifest binds assessment ID, CIR content digest (the current CIR has no native version field), MCUVersion ID when available or a canonical graph digest, upstream artifact IDs/digests and method versions to the requested Phase 6 snapshot. The repository seals an assessment context over that exact view identity and manifest digest. A changed research-only manifest therefore makes a new context even when the Phase 6 view has no new finding. Historical upstream artifacts that cannot be validated remain explicitly unknown at Gates A/B; they cannot silently support a strong positive finding. The Phase 6 view remains the only source of verified prior-art facts.

## 3. Research-informed design principles

The master spec's evidence asymmetry governs the workflow: one eligible, verified direct precedent can support a narrow negative conclusion; failure to find one demands broader falsification before a positive conclusion. Independent first passes reduce anchoring. Role blinding and reversed argument order expose order bias where a dispute could change a gate, verdict, assessability or language ceiling. Selective prediction means abstaining when critical facts are unresolved. These are structural safeguards, not claims of measured live-model accuracy. The accepted Phase 6 reviews add a further rule: immutable repository identity, exact passage ancestry and graph membership are checked at every authoritative handoff.

## 5. Candidate architecture comparison

| Approach | Benefit | Failure mode | Decision |
| --- | --- | --- | --- |
| A. One sequential model plays prosecutor, defender and judge | Lowest orchestration cost | Later roles see and inherit earlier framing; one free-form response can smuggle unsupported evidence or decide its own verdict | Rejected for material adjudication. |
| B. Unrestricted multi-agent debate | May surface objections | Unbounded cost, role drift, citation invention, persuasion replacing evidence and unclear stop conditions | Rejected. |
| C. Controlled independent briefs, bounded rebuttal, neutral counterbalanced adjudication and deterministic permission | Clear authority and audit boundaries, bounded cost and explicit uncertainty | More typed records and orchestration | **Chosen**, with typed evidence-gap escalation through Phases 3–6 (B+). |

## 6. Recommended architecture

The application coordinator owns the lifecycle; domain contracts and policies have no provider SDK dependency:

    repository Phase6AssessmentView + validated upstream input manifest
      -> sealed assessment context
      -> deterministic AdjudicationCasePacket
      -> independent NoveltyProsecutor / NoveltyDefender proposals
      -> material-dispute and typed need policy
         -> Gate A InputClarificationNeed: input resolution or abstention
         -> external ResearchGapRequest: Phases 3–6 -> new sealed context -> new Phase 7 run
         -> otherwise: at most one rebuttal per side
      -> neutral EvidenceAdjudicator; counterbalance deterministically high-impact disputes
      -> validated gate findings -> deterministic VerdictPermissionPolicy
      -> repository-validated FrozenAdjudication -> Phase 8

The role outputs are arguments; the packet is a derived working artifact; the Phase 6 repository is evidence authority; only a committed Phase 7 frozen record is adjudication authority. A neutral summary may be added later for token economy, but it is labeled derived and cannot replace the packet or exact citations.

## 7. Phase 7 lifecycle

The minimum durable run states are CASE_BUILT, FIRST_PASSES_COMPLETE, ESCALATION_PENDING, SUPERSEDED_BY_NEW_ASSESSMENT_STATE, JUDGING, FROZEN, ABSTAINED and FAILED. Rebuttal/counterbalance progress is represented by immutable child artifacts rather than extra run states. CASE_BUILT requires an exact loaded snapshot and sealed assessment context. FIRST_PASSES_COMPLETE requires both separately committed role cases. ESCALATION_PENDING records an accepted external research request without mixed-context adjudication; a Gate A input need instead leads to clarification or a frozen UNASSESSABLE finding. Completed escalation that changes verdict-relevant research or evidence state seals a successor context and atomically marks the old attempt SUPERSEDED_BY_NEW_ASSESSMENT_STATE; the coordinator starts another run at CASE_BUILT. Zero new sources do not bypass that transition. Only a proven true no-op under section 14 may resume the same run. FROZEN and ABSTAINED are successful semantic terminal states; **ABSTAINED still stores a frozen UNASSESSABLE finding** with its reasons. FAILED is operational, never a synonym for UNASSESSABLE. Transitions and predecessor IDs are append-only and repository-validated.

## 8. AdjudicationCasePacket

The application service exposes a repository-backed operation conceptually equivalent to build_adjudication_case(assessment_id, assessment_context_id, repository). It reloads the bound Phase6AssessmentView and validated upstream records under a consistent read. The immutable packet binds assessment ID, sealed context ID, Phase 6 snapshot ID, input manifest ID and digest, as-of, CIR ID and digest, MCU graph/version ID, target IDs and full MCU/combination topology, Phase 2 sufficiency, research branch/coverage/stop/budget state, method versions and provenance. One packet represents one immutable assessment world-state; later coverage, budget or stop facts cannot be injected into it.

It retains exact committed comparison IDs, authorization status, support and scoped subset/remainder, cited source/version/passage IDs and text/locator/attestation, chronology, contradictions, access limitations, lineage, patent and multi-source derived records, failed/excluded/unassessed candidates and unresolved questions. These are typed references plus immutable cited content, not a lossy prose summary. Case packet ID is a canonical hash of the sealed context ID, bound identities, complete normalized content and builder version. Prompt-size selection may omit irrelevant display text for a specific role call only if the omitted material is recorded; no decisive finding can depend on evidence the judge did not receive. The repository revalidates packet dependencies before freezing.

## 9. Prosecutor

NoveltyProsecutor receives the packet in its own first-pass context. A ProsecutionCase binds case ID, assessment/context/snapshot/target IDs, typed challenges, proposed input-clarification needs or external research gaps, limitations and prompt/model provenance. Each challenge has a stable challenge ID, thesis, comparison IDs, source/version/passage IDs, matched elements and relationships, missing elements, material conflicts, chronology analysis, coverage relevance, a structured counterfactual and an effect in DIRECT_CHALLENGE, PARTIAL_CHALLENGE, COMPONENT_CHALLENGE, ANALOGY_CHALLENGE, NO_MATERIAL_CHALLENGE or UNRESOLVED_CHALLENGE. The effect is an argument, never a Phase 6 reclassification or verdict. An unverified hypothesis is marked as the appropriate typed need, with no established-evidence citation. The model is told to seek the strongest supportable falsification, including renamed, historical, adjacent, patent, product and software forms, but cannot search or claim those forms were found unless they are in the packet.

## 10. Defender

NoveltyDefender receives the **same packet** in a separate first-pass context, before the prosecutor case is visible. It assesses neutral packet-derived comparison issues and independently records candidate concessions, missing elements/relations, control-flow and topology differences, population/context limits, chronology problems, analogy or partial inflation, weak access, source stitching and surviving differentiators. A DefenseCase binds the same assessment/context/snapshot/target identities, a defense ID for each point, its Phase 6 references, a concession/objection/unresolved disposition, counterfactual reasoning, limitations and typed input needs or external research gaps. It does not advocate for the user or assign a verdict. After both first passes are committed, a bounded defense rebuttal may address the prosecutor's actual challenge IDs. Conceding an exact direct precedent is a correct outcome.

## 11. Rebuttal protocol

A deterministic comparison of structured first-pass effects, citations, concessions and missing-element claims identifies **material** disputed points. Only those IDs enter rebuttal. Each side gets at most one rebuttal artifact for the whole run; each claim names challenge/defense IDs and packet Phase 6 IDs. No new source may be introduced from memory. Missing external evidence becomes a ResearchGapRequest; missing target meaning becomes an InputClarificationNeed. Neither becomes another debate turn. If no material disagreement exists, rebuttals are skipped. There is no reply-to-reply loop.

## 12. Input clarification and research gap escalation

InputClarificationNeed is a strict typed input problem: need ID, assessment/context/snapshot/target IDs, reason, missing input fields or unresolved structure, material_gate=A, resolution requirement and provenance. It covers unspecified mechanisms, unclear combination topology, unresolved relationship direction, overbroad target scope, missing material conditions and unstable MCU decomposition. It routes to input resolution or abstention, **never** to Phases 3–6 as a research request. Clarified input must be validated and rebound in a new assessment context before adjudication; unresolved material input produces Gate A INSUFFICIENT and UNASSESSABLE. Searching harder cannot repair missing target meaning.

ResearchGapRequest is a strict typed external-evidence proposal: request ID, assessment/context/snapshot/target IDs, requesting stage (FIRST_PASS, REBUTTAL or ADJUDICATION), gap type, reason, research hypothesis, EvidenceFamily values, existing QueryFamily/RetrievalStrategy hints where applicable, material Gate B or C, or Gate D **only** when missing prior-art evidence is genuinely material to the surviving difference, linked challenge/defense/comparison IDs, categorical priority, checkable stop condition and provenance. Gate A is not a valid material_gate. Stop conditions name a specific missing external fact such as RESOLVE_CHRONOLOGY, ASSESS_RELATIONSHIP_IN_PRIOR_ART, CLOSE_ACCESS_GAP or TEST_COVERAGE_BRANCH; they do not promise global saturation. Gap types cover terminology, adjacent domain, patent/product/software coverage, combination/relationship precedent, chronology, access, contradictory evidence and coverage. A validator ensures every linked ID belongs to the sealed context. A request is not a search result.

The GapEscalationPolicy rejects Gate A/input needs and accepts only a missing-external-evidence gap whose resolution could change Gate B/C, an evidence-dependent Gate D state, a permitted claim-specific verdict or a strong-positive ceiling; a Gate D gap additionally requires a demonstrable missing prior-art fact, such as an inaccessible closest historical implementation. Budget and deduplication still apply; explanatory gaps become frozen limitations. The coordinator sends accepted research requests to a Phase 3 planning adapter, then the existing reviewed retrieval pipeline, Phase 5 normalization/provenance and Phase 6 verification. A completed escalation that changes evidence **or verdict-relevant research state** must be included in a new repository-sealed assessment context before any further adjudication. The normal path reloads a new Phase6AssessmentView snapshot with prior applicable work and new outcomes. If only bound Phase 3/4 research metadata changes and the Phase 6 snapshot identity stays the same, a successor context seals the new validated input manifest against that unchanged view; it still starts a fresh Phase 7 run. No prosecutor, defender or adjudicator receives retrieval-provider authority.

## 13. Research budget and stopping

ResearchEscalationBudget records configured BudgetLimits, cumulative BudgetUsage, request IDs issued/accepted/rejected, provider/access blocks, remaining material gaps and a typed stop reason. It reuses Phase 4 BranchState and StopAssessment distinctions: SATURATED is evidenced convergence, while BUDGET_STOPPED and ACCESS_BLOCKED are limitations. Request and loop limits are configurable operational bounds, never proof of sufficient research. Deduplicated requests and no-new-yield prevent spinning on the same gap. NO_NEW_YIELD is not silently SATURATED; SUFFICIENT_FOR_REQUESTED_VERDICT is a gate-relative conclusion supported by coverage facts, not an elapsed-loop count. A completed zero-yield search can change attempts, coverage, budget, access or stop status; those updated facts are sealed in a successor context before Gate B or verdict permission uses them. Exhaustion reduces positive permission where material; it does not erase a valid direct precedent.

## 14. Assessment-context restart semantics

**One authoritative Phase 7 run = one immutable bound assessment world-state.** Every role, rebuttal, judge, gate and frozen artifact carries assessment_id, assessment_context_id and phase6_snapshot_id. When accepted escalation completes and changes evidence, attempted strategies/providers, query or coverage history, BudgetUsage, NO_NEW_YIELD, access failures, remaining gaps, branch stop reason or another bound policy/input artifact, the repository seals a successor context. The old attempt becomes SUPERSEDED_BY_NEW_ASSESSMENT_STATE, preserving requests, costs and arguments for audit. A fresh case packet and independent first passes are mandatory even when the Phase 6 snapshot identity is unchanged and no source was found. Old artifacts cannot be transplanted; their context IDs fail validation.

The same run may resume only after the repository proves a **true no-op**: no new evidence; no changed query/request history or coverage; no changed budget, stop, access or provider state; no changed upstream bound artifact; an unchanged input manifest digest; and an unchanged Phase6AssessmentView snapshot identity. A mere zero-yield report, unchanged snapshot alone or unverified caller assertion is insufficient. A true no-op may leave an operational audit event, but may not inject a new material fact into the sealed packet or alter gate inputs.

## 15. Neutral adjudicator

EvidenceAdjudicator consumes the full case packet, validated structured prosecution and defense cases and at most two bounded rebuttals. It receives no private model reasoning or provider results. It emits per-target structured findings: accepted/rejected/uncertain challenge IDs, exact Phase 6 evidence IDs, disputed material relationships, scoped differences, counterfactual localization, typed input needs or external research gaps and proposed Gate C/D semantic states with reasons. Gate A/B factual ceilings are provided by deterministic evaluators; the judge may comment on materiality but cannot override those facts. It cannot alter Phase 6 support, chronology or precedent labels, search, add a citation, declare a final verdict or produce a probability.

## 16. Blinding and counterbalancing

The judge sees neutral Argument A/B labels and stable argument IDs, not role names, where practical. An internal sealed mapping preserves actual role/model provenance for audit. Before judging, a deterministic consequence check evaluates the two plausible resolutions of each material dispute against the categorical gate and permission policy. A dispute is HIGH_IMPACT if those resolutions could change **any** Gate C state, Gate D state, per-target verdict permission, UNASSESSABLE versus assessable status, maximum claim-language class, claim-specific negative permission, or POTENTIALLY_NOVEL permission. Counterbalancing is **required** for HIGH_IMPACT; otherwise it is not required. The check uses possible semantic consequences, never source count, token count, orchestrator preference, provider price or model confidence. If possible consequences cannot be bounded reliably, treat the dispute as HIGH_IMPACT.

For every HIGH_IMPACT dispute, Judge A receives Argument A then Argument B and Judge B receives Argument B then Argument A, with the same CasePacket, rubric, model/configuration and evidence. Each CounterbalanceRun records run ID, argument order, packet/rubric/model version, structured judge finding and operational provenance; a comparison record links the pair. Both outputs are retained. Blinding is limited when wording itself reveals a role; this is recorded rather than claimed away.

## 17. Judge instability

Normalize judge outputs by target, accepted challenge IDs, decisive evidence IDs and Gate C/D effects, ignoring harmless wording or list order. STABLE means material findings agree; MINOR_ORDER_VARIATION means wording or nonmaterial emphasis differs; MATERIAL_ORDER_INSTABILITY means equivalence, contribution significance, decisive citation or resulting permission differs. Every required HIGH_IMPACT pair is retained and compared; disagreement is never averaged into apparent consensus. If it changes negative versus positive permission or assessability, the affected target is UNASSESSABLE pending resolution. If it changes only potential versus strong positive, the ceiling is POTENTIALLY_NOVEL. Optional heterogeneous escalation may resolve it; otherwise the instability remains a frozen limitation.

## 18. Heterogeneous escalation

An optional provider-neutral JudgePort may run a separately configured model for unresolved high-impact disputes, strong-positive candidates or disputed claim-specific negatives. It receives the same packet and validated arguments; its output passes the same schema and ID gates. Model diversity cannot create evidence or vote a verdict into existence. The policy compares structured findings and records disagreement; unresolved material conflict follows section 17. Ordinary unambiguous cases require no second vendor.

## 19. Gate A — Input Sufficiency

Gate A is primarily deterministic from SufficiencyAssessment.state, CIR unknowns, target profile integrity, MCUVersion/decomposition stability and MCUGraph.unresolved_disagreements. Its result is ASSESSABLE, LIMITED or INSUFFICIENT for **each target**, with exact input refs and missing fields. Explicit Phase 2 INSUFFICIENT cannot be raised by an LLM. EXPLORATORY may yield LIMITED for a sufficiently described target but never strong-positive permission. Missing mechanism, topology, relationship direction, condition or stable decomposition yields an InputClarificationNeed where resolution is possible. If the target's material mechanism/configuration cannot be compared, it is INSUFFICIENT and receives UNASSESSABLE, not positive novelty. Gate A cannot emit a ResearchGapRequest or be repaired by prior-art search. The judge may add rationale but cannot change the deterministic ceiling.

## 20. Gate B — Research Sufficiency

Gate B evaluates applicable EvidenceFamily decisions, CoverageCell/AdaptiveCoverageCell, strategies and providers attempted, StopAssessment, BudgetUsage, Phase 6 exclusions and candidate failures, access limitations, escalation history and unresolved material external-evidence gaps. It reads these facts only from the current sealed assessment context, including a new context after completed zero-yield research. It returns a categorical **permission set** rather than a scalar: CLAIM_SPECIFIC_NEGATIVE_SUPPORTED_BY_DECISIVE_EVIDENCE, MEANINGFUL_BOUNDED_POSITIVE_COMPARISON and/or STRONG_POSITIVE_COVERAGE, plus limitations. The first needs a qualified cited direct or tightly localized substantial one-reference challenge, not broad search saturation. The second needs enough actual relevant assessment to compare the target, with limitations stated; no-hit or wholly blocked research is insufficient. The third requires appropriate applicable-family coverage, adversarial escalation, evidenced convergence, no verdict-critical access/provider gap and no material exclusion. No arbitrary numerical threshold is invented here; configured Phase 3/4 coverage policy and recorded claim relevance determine the gate. BUDGET_STOPPED never implies SATURATED, and an unavailable provider never implies no precedent.

## 21. Gate C — Equivalence Resolution

Gate C records DIRECT_ESTABLISHED, SUBSTANTIALLY_REPRODUCED_WITH_RESIDUAL_DELTA, NO_DIRECT_IN_REVIEWED_SCOPE, DISPUTED or UNASSESSABLE, with exact authorized Phase 6 comparison/graph IDs and source/version/passage refs. DIRECT_ESTABLISHED requires the eligible, supported same-target/same-source-version Phase 6 direct chain; separate sources cannot be stitched. A strong partial comparison may support the second state only when the verified earlier source covers the material core and the residual difference is explicitly localized; its Phase 6 classification remains strong partial. A local no-direct state does not assert global absence. Contradictory, scoped partial and uncertain chronology remain visible and cannot be silently promoted.

## 22. Gate D — Contribution Significance

Gate D is a semantic finding about the **surviving difference**, not value. It is SUBSTANTIVE, NON_SUBSTANTIVE, UNRESOLVED or NOT_APPLICABLE_TO_DIRECT, with a structured differentiator, nearest Phase 6 comparison IDs, causal/mechanism/relationship/constraint/topology analysis, counterfactual and limitations. Terminology, arbitrary parameter choice or cosmetic workflow rearrangement alone are non-substantive; changed causal mechanism, control flow, functional relationship, enabling constraint, meaningful combination topology or attributable new capability may be substantive. The judge must show why removing the differentiator makes the target closer to the nearest precedent. If significance depends on unavailable closest prior art, Gate D may request that specific external evidence; uncertainty about what the user claims belongs to Gate A input clarification instead. Unsupported value claims cannot decide Gate D.

## 23. Deterministic verdict permission

Each immutable GateFinding binds assessment/context/snapshot/target, gate name, categorical state, authoritative basis IDs, accepted judge finding IDs where relevant, limiting factors, unresolved questions, method version and provenance. VerdictPermissionPolicy takes **validated** per-target Gate A–D findings, the repository-loaded Phase 6 view, the matching sealed research/input context, judge stability, research stop state, qualification records and policy version. It recomputes decisive Phase 6 joins and returns an allowed verdict plus reasons and language ceiling. Model-proposed verdict text is ignored. Permission is an intersection of categorical conditions, not an average or numeric minimum.

| Target verdict | Necessary permission conditions |
| --- | --- |
| NOT_NOVEL_AT_CLAIMED_LEVEL | Gate A permits comparison; Gate B has reliable claim-specific negative evidence; Gate C has an eligible one-source direct precedent **or** a single substantially reproducing verified source with an explicitly localized residual delta; Gate D is NOT_APPLICABLE_TO_DIRECT or finds that delta NON_SUBSTANTIVE; no unresolved material dispute undermines the cited scope. A Phase 6 strong-partial class stays strong-partial even when the claim-level conclusion is negative. |
| POTENTIALLY_NOVEL | Gate A specifies the target sufficiently for a bounded comparison; Gate B establishes a meaningful bounded comparison, though strong-positive coverage may be absent; Gate C has no verified direct precedent in the reviewed scope; Gate D identifies a substantive surviving candidate; remaining uncertainties are recorded and do not make the comparison meaningless. It never means global absence. |
| STRONG_EVIDENCE_OF_NOVELTY | All potential conditions plus stable high-resolution input/decomposition, strong applicable-family research with appropriate adversarial escalation, resolved material dispute, no critical access gap, substantive difference, qualified domain and **passed robustness qualification**. This path is currently disabled by section 25. |
| UNASSESSABLE | Required when input cannot define a comparable claim, relevant evidence access/research is too weak for a meaningful comparison, Gate C/D is materially unresolved, or judge instability could flip negative versus positive. Operational failure uses FAILED run state instead. |
| MIXED_CONTRIBUTION_SPECIFIC | An overall composition only, under section 28; never a substitute for per-target verdicts. |

For a clear Phase 6 direct precedent, broad unsuccessful search is unnecessary: a deterministic Gate C check and claim-scope review can permit a negative at that target. An LLM cannot elevate a local Phase 6 no-direct classification into strong novelty. A failed prerequisite cannot be compensated by strength elsewhere. The policy is a pure, independently testable function; repository freeze re-runs it. Its positive-permission inputs have an explicit information order: replacing assessed coverage with an exclusion, SATURATED with BUDGET_STOPPED, a complete passage with inaccessible text, or stable judging with material instability can only keep or reduce positive permission. A new snapshot with genuinely stronger prior art may reduce novelty permission; a new snapshot that resolves a false challenge may increase it, so verdicts are not forced into a naive monotone order across all new evidence.

## 24. Verdict states

The canonical VerdictState enum is retained: STRONG_EVIDENCE_OF_NOVELTY, POTENTIALLY_NOVEL, MIXED_CONTRIBUTION_SPECIFIC, NOT_NOVEL_AT_CLAIMED_LEVEL and UNASSESSABLE. Target findings use all except MIXED, which composes multiple materially different target states. Each finding names target kind (MCU or COMBINATION), exact claim scope, verdict, decisive/supporting/challenged Phase 6 IDs, four gate IDs, limiting factors and language permission. No verdict encodes practical value, feasibility, probability or a scalar novelty score.

## 25. Strong-positive qualification ceiling

RobustnessQualification is typed as NOT_YET_QUALIFIED, QUALIFIED or FAILED and binds to assessment/snapshot/target, qualification method and validation artifact. Phase 7 does **not** run Phase 9 robustness work, so current production defaults to NOT_YET_QUALIFIED and the maximum positive verdict is POTENTIALLY_NOVEL. The strong-positive enum, gate and permission rule still exist and are testable with a validated qualification fixture. A caller-supplied QUALIFIED flag has no authority. Later Phase 9 qualification adds a repository-validated record and triggers a **new frozen adjudication version**, never mutation of an older finding.

## 26. Domain qualification

DomainQualification is similarly NOT_QUALIFIED, QUALIFIED or FAILED, with domain, assessment/snapshot/target scope, method and evidence reference. No empirical domain qualification is invented in Phase 7. NOT_QUALIFIED blocks STRONG_EVIDENCE_OF_NOVELTY but need not block a well-grounded direct negative or a bounded POTENTIALLY_NOVEL finding; its limitation is explicit. FAILED qualification that makes the model's semantic comparison unreliable causes UNASSESSABLE unless deterministic evidence independently establishes the claim-specific negative. There is no arbitrary numeric threshold or calibrated probability. Later Phase 10 work may supply validated qualification without changing this policy interface.

## 27. Value/novelty separation

NoveltySignificance is the Gate D contribution-bearing assessment; ValueMaturity reuses the existing CLAIMED, PLAUSIBLE, SUPPORTED and DEMONSTRATED states for each ClaimedAdvantage. The two fields are stored separately in FrozenAdjudication. Value facts can inform validation requirements but are excluded from Gate C, Gate D's novelty decision and VerdictPermissionPolicy inputs. A novel candidate can have CLAIMED value, and a directly preceded mechanism can have DEMONSTRATED value. High value never upgrades novelty; low value never erases it.

## 28. Whole-assessment aggregation

Each MCU and meaningful combination gets a target finding before overall composition. No vote, mean or source count combines them. If all adequately modeled claimed contributions have the same defensible verdict, the overall state may carry it with its target scope. Materially different target verdicts, or a negative MCU alongside a surviving combination candidate, yield MIXED_CONTRIBUTION_SPECIFIC with the per-target findings intact. A target that is UNASSESSABLE remains visible; it is never silently dropped to make an overall positive or negative. Whole-configuration negativity requires an explicitly modeled whole-configuration/combination target and corresponding one-source support, not separate component precedents. If target coverage itself is incomplete, an unqualified whole-idea verdict is UNASSESSABLE or mixed with an explicit ceiling.

## 29. Counterfactual contribution localization

For each claimed differentiator, a structured CounterfactualLocalization records the actual target ID, nearest authoritative Phase 6 comparison, the element hypothetically removed, remaining differences and whether substantial equivalence would follow. It is analysis of the claim, not an edit to the CIR, MCU graph or Phase 6 evidence. Gate D uses it to distinguish a real causal/control-flow/constraint contribution from wording or implementation noise. If the nearest source or the removal effect is uncertain, the counterfactual is UNRESOLVED and cannot silently justify a strong or negative conclusion.

## 30. Abstention and UNASSESSABLE

Abstention is a successful semantic decision with reasons; it is not an operational crash. UNASSESSABLE applies when the *requested comparison* cannot be made meaningfully: insufficient specification, decisive inaccessible source, material unresolved contradiction, absent relevant research, unresolved decomposition or judge order instability that changes negative versus positive. If comparison is meaningful but research is bounded or future robustness/domain qualification is absent, POTENTIALLY_NOVEL may be permitted with an explicit ceiling and limitations. Unknown chronology, failed candidates, budget stops and access blocks are never transformed into favorable evidence. The frozen result identifies which gate made the comparison unassessable and what research or input would resolve it.

## 31. Frozen adjudication contract

The real Phase 7 FrozenAdjudication is an immutable, versioned contract distinct from the existing Phase 1 fixture class. It binds adjudication ID, run/assessment/sealed-context/Phase 6 snapshot and case-packet IDs, as-of, CIR digest, MCU graph/version ID, target findings, four gate findings per target, prosecution/defense/rebuttal IDs, input-clarification needs, research request and context-supersession history, counterbalanced judge IDs and stability, decisive/supporting/challenged Phase 6 IDs, limiting factors, unresolved questions, overall verdict, NoveltySignificance, separate ValueMaturity findings, permitted claim classes/wording ceilings, forbidden claims, method/prompt/rubric/provider provenance and freeze observation time.

The language-permission contract uses categorical classes: CLAIM_SPECIFIC_NEGATIVE, SCOPED_POTENTIAL, QUALIFIED_STRONG_POSITIVE, MIXED_BY_TARGET, ABSTENTION, COVERAGE_LIMITATION and SEPARATE_VALUE_FINDING. Each class binds a target and the strongest permitted assertion. Current Phase 7 never grants QUALIFIED_STRONG_POSITIVE. Forbidden classes include UNIVERSAL_ABSENCE and CERTAIN_NOVELTY; examples such as “nobody has ever done this,” “no prior art exists” and “definitely novel” remain disallowed. Phase 8 may choose prose within a permitted class, not change the class or target scope.

The contract contains the **minimal exact references plus structured findings** needed to reconstruct the audit path; full Phase 6 text remains in its authoritative snapshot. The repository checks every reference and re-evaluates VerdictPermissionPolicy before it becomes authoritative. A serialized copy is an export, not a source of authority.

## 32. Persistence and authority

Use the existing SQLAlchemy/SQLite repository authority, extended by additive versioned Phase 7 tables (the next schema revision after current v7), rather than a second truth store. Repository-owned input manifests and sealed assessment contexts bind each Phase 6 snapshot to the validated upstream input, coverage, budget, stop, access and provider state. Runs, immutable case/role/input-need/research-gap/rebuttal/judge/gate artifacts, supersession links, qualification references and one frozen adjudication manifest share transaction boundaries with the existing Phase 6 snapshot rows. A completed research action cannot update a bound manifest in place; changed verdict-relevant state creates a successor context, with a new Phase 6 snapshot when its ledger changes and a new sealed manifest/context when only upstream research state changes. Role and judge rows are audit records, not independent verdicts. A freeze transaction reloads the exact Phase6AssessmentView and matching sealed context in the **same database transaction**, validates current content ancestry, graph authority where cited, all target/context/snapshot IDs, complete argument dependencies, gate findings and the deterministic policy output, then commits the frozen manifest. If Phase 6 or context authority is unavailable, freeze fails closed; it does not fall back to JSON, receipt or caller objects. Public load_frozen_adjudication revalidates the manifest, context and Phase 6 dependencies before returning an authoritative finding. Old fixture adjudication JSON is not backfilled as real Phase 7 authority.

## 33. IDs, versioning and idempotence

All Phase 7 contracts use frozen Pydantic v2 models with forbidden extra fields and explicit contract/method versions. Canonical hashes include assessment ID, sealed assessment-context ID, Phase 6 snapshot ID, target and upstream manifest digest, policy/rubric/prompt version and normalized semantic payload. Case, challenge, defense, rebuttal, input-need, research-request, judge-run, gate and frozen IDs each have their own type prefix; a reversed-order judge call has a different order identifier. A repository-allocated attempt token distinguishes intentional new runs over the same context; an exact retry reuses the token and is idempotent. Different model outputs become different immutable artifacts, not conflicting writes under one ID. Observation timestamps and delivery events are separate from semantic identity. New research state, evidence snapshots or validated qualifications produce new artifact IDs, never in-place replacement; an unchanged Phase 6 snapshot ID alone never licenses artifact reuse across different context IDs.

## 34. Audit and provenance

The audit path is FrozenAdjudication → sealed assessment context → gate finding → accepted/rejected argument and counterfactual → Phase 6 comparison/authorized relation → verifier-cited passage/attestation → source/version. A Gate A input path shows InputClarificationNeed → resolved new input context or UNASSESSABLE. Where research escalation occurred, the path also shows run → ResearchGapRequest → accepted/rejected dispatch → Phase 3/4/5/6 run IDs, including zero-yield, coverage, budget and stop outcomes → successor sealed context and, where Phase 6 changed, new Phase 6 snapshot → successor Phase 7 run. A proven true no-op is recorded separately. Preserve role/model, prompt/rubric versions, input/output hashes, token/cost/latency, failure codes and trace IDs without exposing private chain-of-thought or secrets. Trace append follows repository commit; a failed trace delivery is visible and retryable, never evidence of a completed freeze by itself.

## 35. Phase 8 boundary

Phase 8 receives only repository-loaded FrozenAdjudication plus resolvable citation references. It may render, organize, explain and cite within permitted claim classes and language ceilings; it may not search, add evidence, change Gate A–D, alter verdicts, convert local no-direct into universal absence or upgrade value into novelty. A report/export has a frozen adjudication ID and method version and remains derived. The existing minimal Phase 6 fixture report is not the future full Phase 8 compiler.

## 36. Model and provider ports

Application ports separate ProsecutionPort, DefensePort, RebuttalPort and EvidenceJudgePort from domain models. Each call accepts a versioned prompt/rubric ID and immutable packet or bounded role input, and returns a strict proposal plus operational metadata. Prosecutor, defender, rebuttal and judge prompts each require evidence-only references, strict schemas, explicit uncertainty and missing-evidence reporting; role prompts forbid a final verdict, and all prompts forbid memory citations, evidence creation and Phase 6 reclassification. The judge prompt receives only structured role artifacts, not private reasoning. Every model response is untrusted until strict schema revalidation and checks that all targets, comparisons, source/version/passage IDs, effect enums and argument links belong to the bound context and snapshot; malformed output may use only bounded existing structured-output recovery before an operational failure. Provider/model routing, optional heterogeneous escalation and token budgets are runtime configuration; vendor names never enter domain verdict semantics. ResearchEscalationPort hands approved external-evidence requests to existing Phase 3/4 services, then Phase 5/6; it has no direct evidence-write method. InputClarificationNeed uses the input-resolution path and never this port. Untrusted passage instructions remain quoted data with zero control authority.

## 37. Cost-control strategy

Apply cheap deterministic identity, input, chronology, citation and gate-ceiling checks first. Route Gate A input needs to clarification or abstention, before considering external research. Run independent first-pass roles for assessable targets; skip rebuttal when their material findings agree. A verified direct precedent takes a **reduced negative path**: construct a structured challenge, independently check exact claim scope with the defender, perform neutral adjudication, then apply deterministic negative permission. It skips extra debate and broad positive research. Counterbalance is skipped only when the section 16 consequence check finds no HIGH_IMPACT material dispute; if one exists, the two reversed-order calls are mandatory even on the reduced negative path. Heterogeneous judging remains optional after instability. Positive candidates require the fuller adversarial/gap path. Source count, token count, price and confidence never override the counterbalance trigger. None of these savings bypasses Phase 6 authority, a required gate or repository freeze.

## 38. Failure handling

| Condition | Recorded outcome |
| --- | --- |
| Provider/model outage or malformed output after bounded retry | FAILED run stage with diagnostic; no semantic verdict is fabricated. |
| Invented, cross-target, cross-context or cross-snapshot citation | Reject proposal; bounded retry or FAILED, never promote to evidence. |
| Missing material target input or unstable decomposition | InputClarificationNeed; resolve input in a new context or freeze Gate A UNASSESSABLE. Never dispatch prior-art research as its repair. |
| Insufficient evidence or material contradiction | Gate limitation and possibly UNASSESSABLE semantic result. |
| Research provider/access blocked or budget exhausted | Typed stop and Gate B ceiling; never SATURATED by substitution. |
| Completed zero-yield research changes coverage, budget, access or stop facts | Seal a successor assessment context and restart independent Phase 7 reasoning, even if the Phase 6 snapshot has no new source. |
| Material judge instability | Retain both judge outputs; optional escalation, otherwise section 17 ceiling/abstention. |
| Policy-denied model suggestion | Persist rejected proposal for audit; freeze only policy-permitted verdict. |
| Repository/trace failure | No authoritative frozen result until transaction succeeds; publication failure visible and retryable. |

Decision allocation is explicit: case construction, IDs, context/snapshot joins, Gate A input-need routing, coverage and input ceilings, rebuttal count, budget state, HIGH_IMPACT consequence trigger, required counterbalance comparison, verdict permission, overall composition and language ceilings are **DETERMINISTIC**. Prosecutor/defender arguments, contribution significance and dispute interpretation are **SEMANTIC_LLM** proposals. External-evidence gap materiality, equivalence resolution, Gate B claim relevance and research escalation are **HYBRID**: model rationale is allowed, but typed facts and permission ceilings are enforced deterministically.

## 39. Testing strategy

The later implementation plan should start with failing deterministic tests for identity joins, case-packet preservation, five verdict permissions, all four gates, missing-information monotonicity, context restart, budget-stop distinction, role isolation, one-rebuttal cap, deterministic HIGH_IMPACT classification and mandatory reversed-order calls, counterbalance instability, value separation and caller forgery. Test that Gate A insufficiency produces InputClarificationNeed or UNASSESSABLE without research dispatch; Gate B/C gaps and evidence-dependent Gate D gaps may dispatch, while a missing claimed mechanism cannot. Test completed zero-yield research with changed coverage or budget creating a successor sealed context and fresh role passes, a research-only manifest change with unchanged Phase 6 snapshot doing the same, and a repository-proven true no-op resuming the same run. Scripted providers then test direct claim-specific negative, bounded potential, mixed MCU/combination, genuine UNASSESSABLE, scoped partial, research escalation/new context, stale artifact rejection, qualification ceiling and reduced negative path. Integration tests must load the Phase 6 view from the real repository and freeze through the Phase 7 repository; no live network is used. Verification uses the repository's Ruff, format, Pyright and pytest gates. One bounded independent final Phase 7 acceptance review confirms semantics after implementer TDD and nearby self-adversarial variants.

## 40. Adversarial regression strategy

Include persuasive unsupported prosecution, invented defensive difference, role/order bias, a HIGH_IMPACT dispute incorrectly skipped for cost, copied challenge for another target, fabricated or cross-context Phase 6 ID, Gate A missing input misrouted as prior-art research, local no-direct presented as global novelty, budget stop or provider outage presented as research sufficiency, zero-yield research facts injected into an old packet, stitched multi-source direct, patent partials presented as anticipation, high-value novelty inflation, low-value novelty erasure, new evidence mixed into an old debate, evidence prompt injection and a source absent from the packet. Every verdict-semantic defect receives a regression test before a fix. The implementation loop is: invariant → failing test → minimal implementation → focused green → nearby self-adversarial variants → fix existing-invariant violations → next task. Final independent review is acceptance confirmation, not the primary bug-discovery engine.

## 41. Migration from fixture adjudication

The current domain.adjudication.FrozenAdjudication and application AdjudicationEngine/Phase6FixtureAdjudicator support Phase 1–6 compatibility; the real Phase 6 vertical slice explicitly restricts that fixture to UNASSESSABLE. Retain these fixture paths for historical tests until consumers migrate. Introduce the real, richer Phase 7 frozen contract under a distinct module and contract kind; do not coerce it into the fixture's sparse MCUFinding/evidence-edge schema. A real Phase 7 application path loads the repository Phase6AssessmentView and real frozen record; earlier-phase fixture runs remain labeled fixture. The later plan should migrate the real slice at one explicit boundary and keep report generation from silently treating fixture output as Phase 7 authority. No global deletion of fixture types is part of this design.

## 42. Acceptance criteria

Phase 7 implementation is acceptable when deterministic tests prove: direct precedent permits a scoped negative; Gate A missing input produces clarification or UNASSESSABLE and never triggers prior-art research or positive novelty; Gate B/C and genuinely evidence-dependent Gate D requests route through Phases 3–6; weak/budget-stopped research blocks strong positive; different MCU and combination outcomes stay mixed; UNASSESSABLE remains distinct from operational failure; partials never become direct; any completed escalation changing verdict-relevant research state, including zero-yield coverage or budget, seals a successor context and restarts independent roles; only a proven true no-op can resume the same run; old arguments cannot cross context IDs; every HIGH_IMPACT dispute receives otherwise identical reversed-order judge calls, while non-impact disputes may skip them; material order instability lowers permission; high value does not affect novelty; unqualified robustness/domain blocks strong positive; caller-created frozen shapes cannot establish authority; and Phase 8 can consume only repository-frozen findings. The acceptance review must also confirm no Phase 6 semantic modification, no provider-specific domain coupling and no hidden report re-adjudication. Passing fixtures alone is insufficient; a single bounded independent Phase 7 semantic review follows completed implementation. These are Phase 7 criteria, not another Phase 6 gate.

## 43. Explicit non-goals

No Phase 8 nine-question narrative report, Phase 9 full robustness/red-team implementation, Phase 10 empirical calibration, novelty probability, scalar novelty score, unrestricted autonomous browsing, direct model-output evidence authority, Phase 6 reclassification, legal patent opinion, polished user-facing UX or universal prior-art absence claim. Prompt-injection architecture is enforced here; measured live-model resistance remains a later evaluation task.

## 44. Future Phase 9/10 hooks

Versioned robustness and domain qualification records attach to the exact assessment, Phase 6 snapshot, target, method and Phase 7 policy version. Phase 9 may supply robustness outcomes; Phase 10 may supply domain validation, expert agreement and calibration diagnostics. Neither future phase may retroactively mutate a frozen adjudication. A later policy evaluation may create a new frozen version over the same Phase 6 snapshot with validated qualification IDs. Probability language remains forbidden until empirical calibration and a separately approved policy allow it.

## 45. Open risks and chosen resolutions

| Risk | Chosen resolution |
| --- | --- |
| Current Phase 3/4 metadata live partly in run artifacts, not the Phase 6 view | Use a repository-sealed, hash-bound upstream input manifest and assessment context. Changed validated research metadata creates a new context even if the Phase 6 snapshot is unchanged; missing or unvalidated history is UNKNOWN at Gates A/B. |
| Missing target meaning could be mistaken for a research gap | Gate A emits InputClarificationNeed for input resolution or UNASSESSABLE; ResearchGapRequest accepts only missing external evidence at B/C or evidence-dependent D. |
| Zero-yield research could leave a stale case packet | Compare the full bound world-state. Any verdict-relevant coverage, budget, access, provider or stop change seals a successor context and restarts; only the strict section 14 true no-op may resume. |
| Independent defender cannot answer an unseen prosecutor brief on first pass | Both first passes address neutral packet issues; only the bounded later rebuttal responds to prosecutor-specific challenge IDs. |
| A fast negative path could evade neutrality | Keep both independent roles, a neutral scope adjudication and deterministic policy; skip only unnecessary rebuttal and broad research, and counterbalance whenever a dispute is HIGH_IMPACT. |
| Phase 6 strong partial plus trivial delta could be mislabeled direct | Preserve the Phase 6 class; permit a separate claim-level negative only with one verified source, localized residual delta and Gate D NON_SUBSTANTIVE. |
| Role blinding can be imperfect | Hide origin labels, retain sealed audit mapping, require reversed-order judging whenever either plausible resolution changes a section 16 semantic outcome, and record residual instability. |
| Qualification hooks could be forged | Default to NOT_YET_QUALIFIED/NOT_QUALIFIED; accept only repository-validated records bound to the exact snapshot and target. |
| New evidence or research state could mix with old arguments | Mandatory supersession and fresh case/role/judge artifacts for every changed sealed assessment context, including research-only changes with no new source. |
| Large exact passages strain model context | Keep the full packet authoritative; any smaller display is derived, records omissions and cannot justify a decisive finding on omitted material. |
| A second persistence path could recreate Phase 6 authority bugs | Extend the existing SQLite authority with additive versioned Phase 7 tables; exports and caller objects remain nonauthoritative. |

No design-critical decisions remain open. The next step is user review of this specification; implementation planning follows only after that review.
